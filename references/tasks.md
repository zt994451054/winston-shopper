实验性的 `--search <关键词> --tab <ID> --sort sales` 保存 `search_sort` 任务，从综合选中的第 1／2 页切换一次销量排序，每次最多 25 张、8 次观察。检查点保留原地址、点击前快照、动作意图和连续确认候选；恢复不重发点击、不重置计数。`sort_ui_verified` 不能解释为销量算法已验证，详细边界见同一指引。

`--inspect-controls` 创建只读 `search_controls`；`--inspect-price` 创建单次点击的 `search_price_entry`，二者均只支持同关键词第 1／2 页，每次前 25 张卡片、累计 8 次观察。价格入口先保存前快照和点击意图，失败后不补点；后快照不要求页面变化，complete 仅表示描述性检查完成，不能称为价格排序。两种模式不与 sort、pages 或商品模式组合，详见[控件检查](search-and-reviews.md)。

`--inspect-price-hover` 创建 `search_price_hover`，与其他搜索模式互斥。它保留一次真实指针移入意图，将限定控件引用读取计入 8 次观察预留；后端可能滚动到控件。complete 仅表示描述性观察完成，悬停回包不明仍记录在 `acknowledgement_error`，不能升级为动作成功；后续只读，不补发。方向扫描触顶必须报告，详见[悬停检查](search-and-reviews.md)。

商品详情使用 `task-start --task <名称> --bindings <绑定列表> --details`，最多 10 件商品。此模式在一次受保护的 DOM 观察中读取基础快照和已加载详情，不执行点击、滚动或图片下载；中断按只读快照的原预算恢复。具体字段见 [商品结果说明](products.md)。

正文展开使用独立 `--description-expand`，只接受一个绑定，任务为 `product_description_expansion`。一个展开意图、六次含动作保护的内容观察、三个后检查共用原故障恢复预算；没有明确入口就交付已有正文和有限扫描边界，正常详情模式不增加点击。详见[入口归属、连续确认和中断保护](description-expansion.md)。

图片导出是完成详情任务后的独立步骤，见 [图片读取](image-reading.md)。它共用本地平台锁，在 `<state-dir>/images/<task>/receipt.json` 保存请求预留；单图自动重试为零。失败或中断不改变原详情快照，但会阻止同状态目录的新图片请求；已有缓存仍可离线验证和读取。`task-resume`、`task-end` 不清除图片预留。

## 创建与执行

```sh
node scripts/shopping.mjs task-start --task compare-mice --bindings mouse-a,mouse-b
node scripts/shopping.mjs task-run --task compare-mice
node scripts/shopping.mjs task-status --task compare-mice
```

输入 1–50 个绑定名，按淘宝商品 ID 去重；同一任务端点、商品和操作类型固定。原绑定后来被替换不会悄悄改变任务。`complete` 指所有快照操作完成，结果中的 `coverage.status: partial` 仍表示没有取得完整商品数据。

`--plan` 创建的规格任务按商品和组合共同去重，最多 20 个组合。输出中的 `completed`、`failed`、`remaining`、`total_operations` 都以操作为单位；`distinct_products` 单独统计商品数，同一商品的两个组合是两项操作。搜索、购物车和订单任务没有绑定商品，这个字段为 `null`。

恢复时始终使用同一 `--task` 和 `--state-dir`。已完成商品不重复读取，`observed_at` 保留原观察时间。新的比较任务可使用新任务名，不能把改名用于重试失败中的同一任务。

`--services` 使用独立的服务动作日志：每商品 1 次动作预留、8 次读取预留、3 次未确认检查。已打开面板跳过点击；动作记录存在后只读，不因中断、明确未派发或不明回包而清零。故障恢复仍使用下方共有预算，见[服务任务](services.md)。

`--review-categories FILE` 每批一个商品、1–3类、每类前10个主评位置，只读文字。最多一次正常面板打开、每类一次切换、共12次文字采样读取；动作意图和连续观察候选持久保存，已确认分类在停止后仍可交付。新建任务额外保存有界observation_delivery，并独立交付最后有效的未确认文字；较早观察不参与故障恢复后的连续确认，也不改变停止／预算规则。

新建任务还保存panel_lifecycle：全部请求分类确认后，仅恢复初始关闭且明确由本次打开的同标签面板。收尾另限3次状态读取和一次关闭意图，合计最多15次DOM读取，共用原故障恢复预算；关闭后须两次连续确认。收尾失败会暂停或停止，已确认文字保留；初始已开、打开回包不明或标签已变更时不关闭。报告中的dom_observations_reserved仍只计文字采样，total_dom_observations_reserved合计采样与收尾。旧检查点不迁移或补造上述可选字段。详见[分类文字任务](review-text-sampling.md)。

## 默认预算

| 情况 | 执行规则 |
| --- | --- |
| 桥接连接暂不可达、工具超时、文档仍加载 | 同一操作最多自动重试 2 次；首次加重试最多 3 次。等待 5 秒、15 秒 |
| 页面明确频控 | 暂停整个平台任务；用户稍后要求恢复时最多一次冷却后探测。探测失败或后续再频控停止本轮 |
| 验证码、登录 | 用户处理前自动重试 0 次；用户报告完成后只检查一次，仍有验证或该次检查暂时失败则继续暂停 |
| 扩展断开、目标关闭或变化 | 暂停，修复后显式恢复；不自动换标签页 |
| 商品不可用、明确无权、能力不支持 | 单项失败，不重试，可继续队列中其他商品 |
| 结构不匹配、未知遮挡、协议异常或未知错误 | 停止本轮，不把它们归为临时故障 |

指定规格的 `SELECTION_STATE_CONFLICT` 属于结构诊断错误：同一规格组报告多个选中项时停止整个平台队列，不自动重试或确认不明点击。不要把它当作库存不足而继续剩余组合。

评价的 `REVIEW_DRAWER_NOT_VISIBLE` 同样属于诊断停止：已挂载的评价内容在视口之外或被祖先隐藏，不能认定面板已展开。保留原读取预留和动作意图，不自动补点、重试或新建替代任务；它不等同于需要登录或平台频控。

新文字分类任务只有在首次读取另外验证到唯一正常“查看全部评价”入口时，才可进入已预算的一次打开分支；它不会根据屏外内容本身宣称展开成功，也不恢复已停止的旧 `--reviews` 任务。分类内容不变、选中标记冲突或正文归属未确认时停止，不把缺失证据当成一次空分类成功。

每个平台任务累计最多 5 次自动恢复，包含那一次冷却探测。临时故障的等待在执行前预留，累计预算 120 秒；进程重启不返还已经预留的等待和次数。商品之间至少间隔 1.5 秒，这属于操作节奏，不计入故障恢复等待预算。所有底层桥接调用没有内部重试。

当前页面读取没有平台响应头，也没有经过验证的冷却秒数，因此频控后不会定时试探。`--after-cooldown` 表示用户稍后明确要求恢复，不表示冷却条件一定已满足。这里的时间和次数是本地限制，没有证据证明它们是平台认可的安全阈值。

## 暂停后的操作

服务必须常驻：任务停下等用户、节奏等待或命令退出时都不关闭。登录、验证码、限流造成暂停时，先保存暂停状态，再尝试显示对应页面一次；显示失败不覆盖原错误和暂停，也不重连。用户处理后仍沿原任务、原页面恢复。普通流程不提窗，其他有限例外见[窗口规则](setup.md#窗口何时会到前面)。

服务重启后不能自动认回原页面编号，也不自动迁移任务。旧浏览器通道只保留检查点和缓存，不能通过改端点或迁入新连接继续，见[旧结果说明](dedicated-browser.md)。

出现 `TARGET_CHANGED`／`TARGET_MISSING` 时，可先检查目标定位，不消耗页面观察额度：

```sh
node scripts/shopping.mjs task-diagnose --task mouse-search --state-dir <原状态目录>
```

命令只查询原端点的连接和一次本次连接能看到的页面清单，保留任务状态与计数。`matching_target` 表示地址匹配；`other_site_or_browser_page` 表示原 ID 已指向其他网站或浏览器页；`different_search_query` 表示关键词不同；`unsupported_search_url` 表示同一搜索路径的参数不受当前实现支持；`login_page` 只说明地址已到登录入口。`target_mismatch` 是其他未匹配的淘宝／天猫地址。

`tab_not_in_current_window` 是沿用的诊断名称，表示原编号没有出现在本次连接清单里，不证明页面已关闭。Playwright 看不到用户自己打开的页面；先检查原服务和 `instance_id`，不要要求用户切窗口来找页，也不要重连来替换原页面。精确匹配的候选 ID 不会被自动接回；仍按下面的原状态选择操作。诊断命令不是恢复入口，也不会把 `stopped` 改成可运行状态。

| 保存状态 | 后续操作 |
| --- | --- |
| `awaiting_batch` | 购物车分批及旧规格批次：已读结果可交付，`task-run`只回缓存；同任务`task-next-batch`续读，不刷新预算。规格新采集日志自动分批 |
| `retry_wait` | 继续 `task-run`，遵守已保存的时间和预留次数 |
| `waiting_user` | 用户完成登录／验证后，`task-resume --after-user` |
| `waiting_cooldown` | 先保持暂停；用户稍后要求恢复时，`task-resume --after-cooldown` |
| `waiting_connection` | 修复后 `task-resume --after-connection`；新标签页先按下例接回 |
| `partial` | 本轮已结束，返回成功结果和失败项 |
| `stopped` | 保留结果，停止此平台本轮访问并检查原因 |

基础商品结构错误现在可附带`operations[].error.reason`，取值见[商品字段与限制](products.md)。例如`{"code":"PAGE_STRUCTURE_CHANGED","category":"diagnostic","reason":"price_region_ambiguous"}`表示同次读取遇到多个支持价格区。该字段是固定诊断标签，不是商品原文；不改变错误类别、平台停止、等待及恢复预算。旧错误不补造reason；任务回读保留已记录原因且不访问浏览器。原因来自校验顺序的首个失败，不能据此宣称整页仅有这一处问题。

每条命令仍需 `--task <原任务名>`，使用非默认状态目录时带上原 `--state-dir`。`task-resume` 必须选择且只能选择一种 `--after-*`。

同一商品重开后标签页 ID 改变：

```sh
node scripts/shopping.mjs bind --tab <新标签页ID> --binding reopened
node scripts/shopping.mjs task-rebind --task compare-mice --binding reopened
node scripts/shopping.mjs task-resume --task compare-mice --after-connection
```

只能接回原端点上的同一规范商品链接。计数、成功结果与剩余工作均保留；不同商品会返回 `TASK_TARGET_MISMATCH`。

用户明确结束本轮任务时可以执行 `task-end --task compare-mice`。它在本地保留结果和次数，将任务标为 `ended`；旧任务不能再恢复。此命令不会解除平台限制，也不应被 agent 当作获得新额度的自动步骤。

## 中断与并发

- 检查点在每次逻辑读取之前原子提交执行次数，取得结果后再次提交。写入失败立即停止。
- 快照读取中断会按“结果未提交”处理，可以占用正常重试额度重新观察。规格、搜索跳转、旧两页、新1–5页及评价展开任务另有动作意图记录：恢复时先核对已预留动作的结果，不重复派发。新多页最后页已保存时纯本地完成结果，不追加读取。尚未实现的任意开新标签或范围外翻页不能直接套用快照重读规则。
- 用户接管检查和冷却探测的身份也保存在检查点；这两种检查中断后不会自动补发。
- 同一状态目录只允许一个未结束的淘宝任务，执行时持有平台锁；不能改名越过一个暂停或停止的任务。
- 同机进程已确认不存在时自动回收它遗留的锁。进程仍在、权限不足、主机不同、锁损坏时保持 `TASK_BUSY`。若进程恰好在写锁或回收锁期间被终止，需要先确认没有任务运行，再检查并移走 `tasks/.taobao.lock` 或 `tasks/.lock-recovery`；不自动抢占不明锁。
- 所有 agent 应共享同一状态目录。独立目录、其他机器、外部浏览器工具和用户手工浏览不受这把本地锁控制。

## 保存与输出

默认检查点位置为 `~/.consumer-shopping/bindings/tasks/<任务名>.json`；也可随 `--state-dir` 改变。新文件在 POSIX 系统创建为 `0600`。检查点保存目标链接、用户请求的搜索关键词、浏览器定位、执行预算和限定结果，不保存 cookies、账号标识或评价者名称与头像。购物车行和个人订单结果属于私人购物信息，只留本地；项目验证固定使用 `.runtime/verification-bindings`，不得换目录刷新预算。订单保存明确订单号与正常详情入口是本次授权范围，不代表读取联系人、账户档案或付款资料。

输出中的 `attempts` 是逻辑读取尝试数，包含连接检查就失败的尝试；`automatic_retries` 是预留的恢复次数，进程中断可能导致额度已用但读取未发出。顶层重试数包含冷却探测，单项重试数仅指该项的普通故障重试。

任务检查点保留供恢复与复查，未自动清理，也未宣称加密。不要将实际任务数据、浏览器个人资料或 `.runtime/` 一起提交到开源仓库。

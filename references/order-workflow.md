## 范围与入口

新的正常订单请求明确选择原列表前5个已加载订单组中的一单，位置为1–5。先按[连接流程](setup.md)检查 doctor／fresh tabs，确认已有的买家列表标签。编排固定此列表标签，不自动开列表、换窗口或借同地址标签。

```sh
node scripts/shopping.mjs order-workflow-start --workflow <新正常请求名> --tab <原列表ID> --order-position <1至5> --state-dir <原私有状态目录> --json
node scripts/shopping.mjs order-workflow-run --workflow <同一请求名> --state-dir <同一状态目录> --json
node scripts/shopping.mjs order-workflow-status --workflow <同一请求名> --state-dir <同一状态目录> --json
```

名称限定1–48个小写字母、数字、下划线或连字符。三个子任务名固定为 `<名称>-list`、`<名称>-entry`、`<名称>-body`，在创建任何子任务前保存计划。已有同名任务拒绝导入，不能套用旧任务／研究收据或换名继续失败额度。创建和 status 不访问浏览器。

| 阶段 | 复用能力 | 来源与完成边界 |
| --- | --- | --- |
| list | 原前5组 `order_snapshot` | 原列表 ID；每组最多10商品，保留此次观察时间。选择位置不存在即停 |
| entry | 原 `order_detail_check` | 固定 list 子任务的选定位置、编号和链接；一次受保护鼠标意图，排除旧详情页，确认本次唯一新标签。完成仅表示入口／页面检查 |
| body | 原 `order_body_snapshot` | 固定 entry 确认的新标签 ID；fresh tabs 精确地址及正文唯一打印编号保护。最多10个已加载商品、流程和金额原文 |

有可见受支持错误面板时保留入口结果，不创建正文子任务。缺页、登录／验证或频控按原阶段条件暂停；不换订单找触发，也不重开、刷新或借同号旧页。编排不新增正文读法、订单改动、购物车改动、下载或视频操作。

## 保存与共享预算

元数据在同一私有状态目录 `order-workflows/<名称>.json`，子任务仍在 `tasks/`。目录700、文件600、原子替换。编排与原任务共用平台锁，一次只运行一个子阶段；完成阶段保存完整任务文件 SHA-256，回读核对固定任务、端点、来源链和原字节。

各阶段保留原保护：列表6内容次，入口8内容／6清单／8执行及1动作意图，正文6内容／8清单／8执行。清单计数遵循原阶段，列表的地址确认不新增独立清单计数。包装不把阶段次数合成一个可挪用的新读额度。

整条链额外共享：合计2次用户／连接／频控显式恢复，每次5000ms；平台重试最多5次，其中频控探测最多1次；各阶段原等待预留之和不超过120000ms，包括入口正常5000ms。各阶段的原自动故障重试仍最多2次、等待5000／15000ms。跨阶段检查在子任务落盘前执行，超限即停，后续 IO 不派发；已落盘预算不退还、跨日不清零。拒绝重试预留发生在真实故障之后时，包装错误的 `cause` 保留该安全错误码，原子任务已保存的首错和预算不改。

阶段间另有两次正常1500ms间隔，共3000ms，分别提前保存 `not_before` 和预留量，不占原故障等待额度。中断接续只等待尚未经过的间隔，已完成阶段不重读；子结果已保存但包装未交接时，仅核对原结果并提交阶段完成。点击未知回执沿原入口状态观察新页，不重复点击；恢复等待中断沿原子任务预留继续，不再扣一次恢复。

未完成或 stopped 的编排占用同平台保留，拒绝换名创建另一编排／任务和直接运行其子任务。已完成子任务可经普通任务命令回读缓存，修改和单独结束仍拒绝；结束整轮使用工作流命令。

## 暂停、恢复与结束

```sh
node scripts/shopping.mjs order-workflow-resume --workflow <原名称> --after-user --state-dir <原目录> --json
node scripts/shopping.mjs order-workflow-resume --workflow <原名称> --after-connection --state-dir <原目录> --json
node scripts/shopping.mjs order-workflow-resume --workflow <原名称> --after-cooldown --state-dir <原目录> --json
node scripts/shopping.mjs order-workflow-end --workflow <原名称> --state-dir <原目录> --json
```

每次 resume 只接受与当前暂停条件匹配的一种标记。用户登录或验证码必须由用户完成；恢复连接须回到原窗口和保存标签。没有待恢复阶段、完成或 stopped 时拒绝新增恢复额度。停止后 run／status 只交付原失败和部分观察；显式 end 本地结束未完成子任务并释放整轮保留，不增加浏览器动作，也不允许重新运行已结束轮次。

complete／ended 后工作流 run、status、end 均只回原缓存。complete 表示三个限定阶段完成；ended 表示主动结束，不能解释为采集完成。剩余预算不补填。

## 交付

报告的 `workflow_kind` 为 `single_order_workflow`，`result.scope` 为 `single_order_read_workflow`：

- `result.observations.list` 保存选定订单行、原列表任务／观察时间和覆盖。
- `result.observations.entry` 是原入口检查结果，保留页面检查时间与原列表来源。
- `result.observations.body` 是原正文任务结果；真正的正文仍在其 `.body` 中，保留独立时间、商品位置及 partial 覆盖。
- `stages[]` 保留每个原任务名、状态、失败、内容／清单／恢复预算和执行次数；`budget` 提供原计数之和、固定共享上限及阶段间隔。

没有取得的阶段为 null。不同时间的状态、商品与金额保持独立，不相加或回填。`workflow_complete` 与完整商品集、账户身份、结算证明分别表达；后三者仍未验证。真实数据只保存本地，公开测试全部使用合成值。

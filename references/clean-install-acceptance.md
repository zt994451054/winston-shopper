# 纯净环境验收

在一个**从没装过本 Skill 的环境**里，从安装开始把三个平台的主要功能各跑一遍，确认别人拿到安装包后也能用。全程大约 2～3 小时，其中多数时间在等操作节奏的间隔。

## 1. 选一个纯净环境

推荐在这台 Mac 上新建一个 macOS 用户（系统设置 → 用户与群组 → 添加用户），或者使用另一台 Mac。新用户有自己的主目录、Chrome 资料、扩展和登录状态，才能测到第一次安装。只在原用户下换个目录不算纯净。

换 macOS 用户前，在原用户的 Skill 目录先确认任务已收尾，再运行：

```sh
node scripts/shopping.mjs bridge-stop
```

然后退出原用户的 Chrome。默认端口为 `19825`；如果原服务使用自定义地址，停止时带上同一 `--endpoint`。不要通过查端口、杀不明进程来腾位置。回到原用户后可在原安装目录用 `bridge-start` 重新启动，但重启不能恢复旧任务的页面编号。

## 2. 准备前提

| 项目 | 做法 | 检查 |
| --- | --- | --- |
| Node.js 22 或更新 | [Node.js 官网](https://nodejs.org/en/download) 安装，带 npm | `node --version` 显示 v22 或更高，`npm --version` 有输出 |
| Google Chrome | 系统里已有就直接用 | 能打开 |
| Claude Code | 按官方说明安装并登录 | `claude --version` 有输出 |

## 3. 安装 Skill

把当前发布的安装包拷进新环境，核对 SHA-256 与发布时给出的一致。以下命令中的“版本号”替换为实际文件名，不使用旧版安装包验证新版通道：

```sh
shasum -a 256 ~/Downloads/winston-shopper-版本号.tar.gz
mkdir -p ~/.claude/skills
tar -xzf ~/Downloads/winston-shopper-版本号.tar.gz -C ~/.claude/skills
cd ~/.claude/skills/winston-shopper
```

## 4. 扩展、令牌和服务

按顺序完成，不跳过第一次准备：

按[首次准备](setup.md#首次准备)走一遍，每一步看 `setup` 的 `status`：

1. `setup --install`：依赖装好、锁文件核对通过，`status` 变成 `needs_extension`。
2. `setup --open-store`（用平时的资料）或 `setup --open-store --new-profile`（新建专用资料）：Chrome 打开商店页，`status: store_opened`；点“添加至 Chrome”、确认后再运行 `setup`，`status: needs_token`，`extension.profiles` 列出装了扩展的资料。两种方式最好各验一次。
3. 在扩展里点“复制”，告诉 AI 复制好了；AI 运行 `token-save`，返回 `token_saved`、`clipboard_cleared: true`；再运行 `setup`，`status: ready_for_bridge_start`。不把令牌发给 agent 或贴进命令参数。
4. 登录要用的平台；京东订单详情需要允许 `order.jd.com` 弹出窗口。
5. `bridge-start`（不带 `--profile`）自动选用装了扩展的资料；再运行 `doctor` 确认就绪，用 `page-open` 打开第一张程序页面。

```sh
node scripts/shopping.mjs bridge-start
node scripts/shopping.mjs doctor
node scripts/shopping.mjs page-open --search "罗技 M330"
```

| 检查 | 通过标准 |
| --- | --- |
| 第一次 `bridge-start` | `status: bridge_connected`、`started: true`、`state: ready`、`extensionConnected: true`，返回 `instance_id`；连接时窗口会跳一次 |
| 不带 `--profile` 再运行 `bridge-start` | 复用保存的资料和同一个 `instance_id`，`started: false`；不另连扩展、不再因连接提窗 |
| `doctor` | `status: ready`，`connection.protocol: playwright-extension`、`connection.state: ready`、`connection.extension_connected: true`；即使没有任务页面也就绪，不启动或重连、不读页面 |
| `page-open` | 返回 `tab_id`，地址核对成功；遇到登录或验证时停下处理，不反复开页 |
| `tabs` | 能列出上面程序打开的页面；用户自己打开的标签页不在清单里，不能按浏览器总标签数对账 |
| `node --test` | 最后显示 `fail 0`；只使用合成数据和本地模拟服务，不访问电商平台 |

试开的搜索页也计入节奏，与后续搜索类请求至少隔 10 分钟。无需继续时用 `page-close --tab <返回的tab_id>` 关掉试开页面；不要停止服务再开始功能验收。

服务在任务之间、暂停等用户、退出后重新打开 Claude Code 时都要保留。不要把 `bridge-stop` 放在每条命令或每轮脚本的退出清理里；服务重启后无法自动认回旧页面。

平时读取不提窗；连接时跳一次、京东订单详情弹出页被带到前面、后台的淘宝价格移入与京东分类评价先显示页面，均是约定行为。登录、验证码、限流停下后，保存暂停状态再显示对应页面一次；显示失败应保留原错误。淘宝价格任务运行期间，鼠标不要经过装了扩展的 Chrome 窗口。细节见[窗口规则](setup.md#窗口何时会到前面)。

## 5. 验收方式

功能验收**用说话的方式**做，这是别人真正使用的方式：在任意一个新目录里打开 Claude Code，用一句话提要求，看它是否自己找到 Skill、选对命令、如实交付。每一项都检查：

- **找到 Skill**：它自己调用了 `winston-shopper`，没有改用别的浏览器工具或自己写脚本开网页；
- **结果对得上**：交付的内容和你在 Chrome 里看到的页面一致（抽查 2～3 处）；
- **说清楚范围**：它说明了读了多少、哪些没读（例如“只读了首屏”“后面的卡片没画出”）；
- **只读**：没有加购、下单、改数量；拼多多的规格抽屉读完关上了，没有进入订单页；
- **没有隐私**：交付和导出的报告里没有收货人、电话、地址、支付方式、物流单号；
- **页面收尾**：程序打开的标签页，读完后可以让它用 `page-close` 关掉。

**节奏**：会打开、翻动或重排搜索页的请求（下表标“搜索类”的）之间至少隔 10 分钟；其他请求之间隔 3 分钟。不要连着发。遇到登录、验证码或限流页面，它应该停下来告诉你，由你在 Chrome 里处理；处理好了再让它继续。

## 6. 功能清单

按顺序做。“说法”可以照抄，也可以换成你自己的话和商品。

### 淘宝／天猫

| # | 类型 | 说法 | 看什么 |
| --- | --- | --- | --- |
| T1 | 搜索类 | 帮我在淘宝搜“罗技 M330”，读前 2 页，列出前 10 个商品的标题、店铺和价格 | 2 页、商品不重复，覆盖说明里有页数 |
| T2 | 搜索类 | 淘宝搜“罗技 M330”，按价格从低到高、只看 40～80 元的，读第 1 页 | 价格都在区间内、从低到高 |
| T3 | 其他 | 打开 T1 结果里的第一个商品，读它的规格、参数、服务说明和详情长图 | 规格名称和页面一致，长图张数合理 |
| T4 | 其他 | 读这个商品的评价，挑两个分类各读一些 | 每类最多 10 条，有正文和分类名 |
| T5 | 其他 | 读我淘宝购物车前 10 行，告诉我哪些买不了 | 不能购买的行附原因原文 |
| T6 | 其他 | 读我淘宝订单列表第 1 页，再打开第 1 单看详情 | 订单数与页面一致；详情有状态和金额 |
| T7 | 其他 | 把 T2 的结果导出成 CSV 放到桌面 | 文件能打开，内容和交付一致 |

## 7. 记录结果

每一项记下：时间、通过／不通过、不通过时它说了什么（错误码和原话）。不通过时不要让它反复重试，把记录发给开发者即可。

验收完：

- 确认任务已收尾后，在新用户的 Skill 目录运行 `node scripts/shopping.mjs bridge-stop`，再退出 Chrome；
- 新用户的任务状态目录 `~/.consumer-shopping/` 有私人购物数据，Skill 的 `.runtime/` 有令牌和服务记录，两者都不要分享；不再需要时连同新用户一起删除。

# 搜索价格排序、区间与缓存核对

2026-10-12 起，淘宝搜索第 1 页的**价格升序／降序和价格区间已有正式任务**（`search_price`），并已在[节奏控制](pacing.md)下通过实页验收：升序、降序、区间 40～60、降序＋区间 4 个任务全部完成。下文“准备请求”“核对已有搜索缓存”两节是 10-10 的离线合同，仍然可用。

## 正式任务

```sh
node scripts/shopping.mjs task-start --task price-asc --search '罗技 M330' --tab <标签ID> --sort price-asc
node scripts/shopping.mjs task-start --task price-range --search '罗技 M330' --tab <标签ID> --min-price 40 --max-price 60
node scripts/shopping.mjs task-start --task price-both --search '罗技 M330' --tab <标签ID> --sort price-desc --min-price 40 --max-price 60
node scripts/shopping.mjs task-start --task price-pages --search '罗技 M330' --tab <标签ID> --sort price-asc --min-price 30 --max-price 100 --pages 3
node scripts/shopping.mjs task-start --task tmall-free --search '罗技 M330' --tab <标签ID> --source tmall --filters 包邮 --sort price-asc --pages 3
node scripts/shopping.mjs task-run --task price-both
```

- **窗口与鼠标**：页面在后台时，真实移入前程序会先把该页切到前面；已可见时不提窗。**整个淘宝价格任务运行期间，用户鼠标不要经过装了扩展的 Chrome 窗口**，否则会收起价格菜单；其他窗口可以照常使用。服务保持运行，暂停也不重连。
- **开始状态**：标签必须是同一关键词、综合排序、未筛选的第 1 页，且没有打开任何价格浮层；不满足时以 `PRICE_START_STATE_UNSUPPORTED` 停止，此时还没有任何页面动作。只支持扩展连接，不能与 `--sort sales` 或各类 `--inspect-*` 组合。金额规则同下文请求合同。
- **固定步骤**：建任务时根据请求生成步骤清单并保存，之后按清单执行：
  1. 读基准页，然后把鼠标移到“综合”上，作为中性起点。
  2. 有排序方向时：移到“价格”→ 读到方向菜单 → 用带保护的页面脚本点击“从低到高”或“从高到低”→ 两次读取一致，确认“综合”已不再选中、商品列表或总页数已变化。
  3. 有价格区间时：经“综合”移到“区间”→ 面板打开且输入框为空 → 在同一步里连续填写请求的边界（填写前先确认面板开着、输入框为空）→ 核对输入值 → 用带保护的脚本点击“确定”→ 两次读取一致，确认“区间”已选中 → 重新打开面板，核对输入框仍显示请求的金额。
  4. 有排序方向时，再次打开价格菜单，核对唯一粗体选项就是请求的方向。
  5. 最后两次读取一致，作为最终结果。验证用的浮层可以保持打开，它不影响商品和分页。
  6. 加 `--pages N`（2～5）时（2026-10-13 起，任务格式第 5 版），第 1 页确认后逐页翻页：
     - 每页先用带保护的脚本点一次“下一页”。点击前，当前页码和已保存的商品顺序都必须对得上。
     - 然后两次读取一致，确认以下各项：
       - 页码已变成目标页；
       - 总页数与第 1 页设置后相同；
       - 有排序方向时，“综合”仍未选中；
       - 有区间时，“区间”仍选中；
       - 商品和上一页不同。
     - 还停在上一页的读取，记为 `page_not_reached`，不重复点击。
     - 读到最后一页后，经“综合”重新打开区间面板和价格菜单，核对区间数值和粗体方向仍在。
     - 结果页数少于请求时，“下一页”是灰的，不点击，保留已读的页，直接做最后一页的核对，`end_reason` 为 `last_page`。
     - 实测（2026-10-13）：翻页只改变网址里的页码，不带排序信息，所以只能靠页面上的这些标记判断条件是否还在。
- **动作规则**：每个动作先保存意图再派发。只有确定没有派发时才释放这次预留；回执不明或进程中断时，只记录为不确定，交给后续读取去核对，绝不重发。读取次数（含读取失败）有总上限，每一步也各有上限；超限分别报 `ACTION_OUTCOME_UNKNOWN`、`PRICE_CONTROL_NOT_CONFIRMED` 或 `ACTION_OBSERVATION_LIMIT`。动作之间至少间隔 1.5 秒；鼠标移动命令单独给 15 秒超时，因为实测回执约 5 秒。
- **天猫与包邮**（2026-10-13 起，任务格式第 6 版）：
  - `--source tmall` 选页面上方的“天猫”来源标签，`--filters 包邮` 选排序栏下方筛选行里的“包邮”。目前只支持这两个。
  - 可以单独使用，也可以和价格方向、区间、`--pages` 组合。
  - **顺序固定**：先天猫，再包邮，最后才是价格控件。原因是实测（2026-10-13）切换“天猫”会清掉已选的筛选项。
  - **点击与确认**：每个条件点一次，之后两次读取一致才算生效。
    - 天猫的标记：“天猫”标签带 `actStyle--` 样式，网址变成 `tab=mall`。读取时“天猫”页和“所有宝贝”页被当作不同页面，绝不混用。
    - 包邮的标记：“包邮”带 `selected--` 样式。网址和总页数不一定变化，不能拿来判断。
    - 点了“天猫”后，读到的仍是“所有宝贝”页，记为 `source_not_reached`，不重复点击。
  - **起点**：开始时必须是“所有宝贝”且没有选任何筛选项，否则以 `PRICE_START_STATE_UNSUPPORTED` 停止，原因记为 `source_not_default` 或 `filters_preselected`。
  - **持续核对**：之后的每次读取，包括每一页，都核对已设好的条件仍在。条件丢了就记下 `source_lost` 或 `filter_lost`，停止，不自动重新点击。
  - **只设条件**：不请求价格时，不移动鼠标，显示价核对为 `not_requested`。
- **浮层被关时重开一次**（2026-10-13 起，任务格式第 4 版）：价格菜单和区间面板只在鼠标停在对应标签上时保持打开，用户的真实鼠标划过页面就会把它们关掉。
  - 某一步发现需要的浮层关了：如果是点击或填写之前发现的（`PRICE_CONTROL_UNAVAILABLE`，什么都没发出），或者是核对读取时发现的（`direction_menu_closed`／`range_panel_closed`），就把鼠标先移到“综合”、再移回原标签，重开一次，然后重做这一步。
  - 每步最多重开一次，整个任务最多三次。两次鼠标移动和其他动作一样，先保存再发出，中断后不重发。重开记录在结果的 `action_evidence.overlay_reopens` 中。
  - 已填的金额如果因为面板关闭而丢失，不会重填；之后的核对读取会发现，任务按原规则停止。
  - 每条“读取不符合”的记录多了 `page` 字段，记下当时页面是否可见、浏览器窗口是否有焦点，用来区分“被用户操作打断”和“页面结构变了”。
  - 调用方应提前提醒用户：整个价格任务运行期间，鼠标不要经过装了扩展的 Chrome 窗口；其他窗口可以照常使用。
- **暂停**：登录、验证码按现有规则暂停；保存暂停状态后显示对应页面一次，显示失败不覆盖原错误。已登录但商品区只显示“网络信号走丢”时，报 `SEARCH_RESULTS_UNAVAILABLE`，按限流处理：整个平台暂停，只有用户之后明确要求恢复，才用 `--after-cooldown` 试探一次。
- **换标签**：做过任何鼠标动作后不允许 `task-rebind`，因为新标签不带已应用的状态；第一次动作之前可以换到同关键词的第 1 页。

结果在 `operations[0].result` 中：

| 字段 | 内容 |
| --- | --- |
| `before`／`after` | 动作前和最终的第 1 页快照，最多 50 张卡片（2026-10-14 之前开始的任务为 25 张，见 `limits.cards_per_observation`），按平台原顺序；网址前后不变 |
| `applied` | 方向：“综合”已不再选中，重新打开菜单时粗体的是请求的选项。区间：“区间”已选中，重新打开面板时显示的输入金额 |

| `displayed_price_check` | 用最终页的显示价逐件核对顺序和区间，复用下文缓存核对的规则 |
| `displayed_price_order` | 按显示价在本地重新排序的列表（只有区间时默认升序），标注 `platform_order: false`，并保留每件商品的平台页码和位置 |
| `applied.source`、`applied.filters` | 只在请求天猫或包邮时出现：生效的来源和筛选项，以及它们的页面标记 |

## 准备请求

```sh
node scripts/shopping.mjs search-price-plan --search '罗技 M330' --sort price-asc --min-price 10 --max-price 100
node scripts/shopping.mjs search-price-plan --search '罗技 M330' --sort price-desc
node scripts/shopping.mjs search-price-plan --search '罗技 M330' --max-price 100
```

- `price-asc`／`price-desc`表示期望平台价格方向；不映射为未验证的平台参数。
- 最小／最大值均可省略，边界包含在内。至少需要方向或一个边界。
- 金额必须是无空白、无货币符号的非负十进制字符串，整数最多9位、小数最多2位；非零整数不接受前导0。不接受指数、负数、分隔符或浮点舍入。`0.1`规范为`0.10`及10分，最小值不得大于最大值。
- 查询沿现有1–100字符合同规范化。其他筛选项，例如包邮、旗舰店、类别和权益资格，尚未接入。

命令输出 JSON，`status: waiting_layout_evidence`，包含规范`request`及按意图列出的`required_evidence`。`platform_sort_implemented`、`platform_filter_implemented`和`platform_applied`均为false；没有浏览器访问、任务创建、平台锁、预算预留或状态保存。这个状态表示请求已准备，不能将其当作可执行的平台任务。没有`run/resume`接口，也不会以缓存核对替代平台操作。

## 核对已有搜索缓存

```sh
node scripts/shopping.mjs search-price-check --task '<已有搜索任务>' --state-dir '<原状态目录>' --sort price-asc --min-price 10 --max-price 100
```

只支持完整的`search`、旧`search_pages`和新`search_collection`缓存。先沿原`loadTask`校验来源、结果和预算；未完成返回`CACHE_NOT_COMPLETE`，其他任务类型返回`UNSUPPORTED_CAPABILITY`，篡改结果返回`INVALID_CHECKPOINT`。不会执行、恢复、结束或改写原任务，未确认分页候选也不会参与核对。

输出为`scope: cached_displayed_prices`，检查保存记录的**原顺序**和展示价，不重排、不过滤掉记录、不改变页面排名。保留每页 URL、采集时间、覆盖／省略数，以及每条商品的字符串编号、原页码／位置、链接和价格原文。跨页同一商品的不同观察仍各保留一条；核对时间单列为`reviewed_at`，不代替采集时间。

只有`single_displayed`价格参与精确分值比较。起价、区间价、无法解析价格保持未知；不将区间最小值当作特定 SKU 的价格。连续已知价格出现倒序，可以反证原样本单调性；若已知部分符合但仍有未知价，方向为不确定。相等价格允许，只有一个确定价格也不足以确认方向。价格区间按包含边界核对，每条记录保留`within/outside/unknown/not_requested`。

| 状态 | 含义 |
| --- | --- |
| `matched_sample` | 保存的确定展示价样本符合所请求条件 |
| `contradicted_sample` | 保存样本存在已知倒序或区间外展示价 |
| `inconclusive_sample` | 含未知价格，或方向没有足够比较点 |
| `not_requested` | 此项未请求检查 |

全部结果仍为partial，`platform_applied`、`platform_sort_verified`、`platform_filter_verified`均为false。即使样本符合，也不能证明控件已应用、平台排序算法、全部结果、优惠资格、SKU关联或实付。跨页采集发生在不同时间；检查只针对保存样本序列。

两个新命令在构造浏览器桥接前分流，不接受`--endpoint`、`--tab`、`--pages`等浏览器参数。`search-price-check`不接受替换查询的`--search`；查询取自原来源。现有`task-start --sort sales`及原任务结构保持，新价格参数不能混入旧入口。

## 2026-10-12 真实控件证据

已经在真实搜索页上各操作一次升序、降序和区间 40–60，三者都生效；降序与区间可以叠加。详见控件观察记录。要点：

- 网址在三种操作后都不变，状态只能从界面判断。“综合”未选中、对应箭头变为橙色，是持续存在的应用标记。
- 当前方向需要用真实鼠标移入“价格”重新打开浮层，从粗体项判断；当前区间需要移入“区间”，从输入框的值判断。
- 方向选项和“确定”都是没有交互角色的普通元素，只能在浮层可见、文字唯一匹配时用页面脚本点击。区间输入框可以取得引用，用真实文本输入填写。
- 平台排序和筛选所用的价格与卡片显示价不一致：升序前几位不单调；区间 40–60 筛选后，当前页 47 件中有 1 件显示 ¥72。所以样本核对仍会得到 `contradicted_sample`，`sort_verified` 不提升。

正式适配尚未实现。下面关于前置条件的描述是此前的时点；新的控件来源已经满足，只差实现和正式任务验收。

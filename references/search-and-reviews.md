# 搜索与展开评价

价格升／降序及区间请求可以通过独立`search-price-plan`准备；`search-price-check`只核对原搜索缓存的展示价和原排名。两者不执行平台控件；平台价格排序／筛选尚未实现，见[请求与缓存核对](search-price-filters.md)。下方既有浏览器入口仍按原正常访问许可及预算执行。

这两种任务复用同一平台队列、暂停条件、锁和重试预算。需要先完成 [环境准备](setup.md)，恢复规则见 [任务说明](tasks.md)。程序只执行固定的页面操作，不使用隐藏接口或跟随广告跳转链接。

## 关键词搜索

在浏览器准备 `https://www.taobao.com/` 首页，执行 `tabs` 取得它的 ID（`kind: search_home`）。也可选择已打开的同一关键词首屏（`kind: search`）。列表不会输出其他搜索页的关键词；有多个候选且无法确定目标时询问用户。

```sh
node scripts/shopping.mjs task-start --task mouse-search --search '罗技 M330' --tab <标签页ID>
node scripts/shopping.mjs task-run --task mouse-search
```

- 输入一个 1–100 字符的关键词。只支持 `s.taobao.com/search`、第一页、全部类别；识别已知跟踪参数并移除，未知筛选参数拒绝处理。
- 原页面必须是精确的 HTTPS 淘宝首页，或同一关键词首屏。不会覆盖其他关键词、商品、私人页面，也不会自动创建标签页。
- 从首页跳转前保存意图；已有同一搜索结果时直接读取。跳转回复丢失后检查最终页面，不再次提交搜索。
- 读取最多 50 张已加载商品卡片。按商品 ID 去重，保留原始 `position`；位置空缺可能对应重复商品或不支持的链接。
- `items` 包含规范链接、商品 ID、标题、店铺、销量文案、搜索卡片展示价格及其原文。价格条件和优惠资格未验证，搜索价格不能直接当作确定实付。
- `cards_seen` 是页面已加载卡片数；`cards_scanned` 是本次扫描数；`duplicates_omitted` 和 `unsupported_cards_omitted` 分别表示重复和不支持链接的省略数。它们不是全站匹配总量。
- 广告跳转等无法直接核实商品 ID 的卡片不跟随、不猜测商品身份。全页没有可解析商品或结构缺失时停止，不能以空数组断言“没有商品”。

默认搜索没有自动筛选、排序、翻页或无限滚动。结果明确保留 `sort_verified: false`、`filters_verified: false` 和未知总量。搜索输入框与页面关键词会再次校验；这不是对平台排序算法的验证。

搜索目标不匹配时，先用 `task-diagnose --task <原任务名>` 区分当前窗口未列出、原 ID 已到其他页面、关键词不同和不支持的搜索参数。扩展只列当前 Chrome 窗口，不能仅凭缺失就认定已关闭。首屏读取在清单缺失时可对原精确保存 ID 做只读地址核对，要求同关键词、无排序／筛选的第 1 页；已列错误目标不启用后备路径。内容脚本仍再次检查身份和验证信号。此能力不聚焦窗口、不发现其他窗口的标签，也不放宽导航：未列出的首页不能被自动导航。地址核对仍失败时才协作恢复页面。确需恢复页面时，由用户打开同一关键词首屏，再在 `waiting_connection` 状态接回原任务：

```sh
node scripts/shopping.mjs task-rebind --task mouse-search --tab <新标签页ID>
node scripts/shopping.mjs task-resume --task mouse-search --after-connection
```

重绑时检查新标签页身份，不重新分配动作或重试额度。搜索任务是一项操作。顶层 `distinct_products` 只统计按商品绑定的任务；搜索、购物车和订单任务没有绑定商品，因此为 `null`（2026-10-12 前为 0）。实际返回的商品数看 `operations[0].result.items.length`。

## 搜索1–5页续读（新模式）

新显式 `--pages N`创建 `search_collection`，N为整数1–5，每页最多50张已加载卡片（2026-10-14 之前开始的任务为前25张）。逐页保存、每个相邻转换至多一次意图、两次连续确认；登录／连接／冷却恢复合计2次、每次5000ms，跨页累计。自然末页需页码等于展示总页数且下一页禁用。保留每页时间和来源，分别统计记录数／去重商品数，详见[新模式命令、预算和边界](search-collection.md)。不指定pages仍是原首屏模式。新1–5页流程的离线测试与旧两页实页证据分别记录。

## 历史限定两页读取（一个关键词实测通过）

以下描述兼容的旧 `search_pages`任务：当时 `--pages 2`创建此种任务；现在相同命令创建上面的新模式，旧检查点、结果和预算不改。旧任务必须从已经打开的同关键词第1页开始，每页前25张卡片；仅有限实页证据，不升级为新多页验收。

```sh
node scripts/shopping.mjs task-start --task mouse-two-pages --search '罗技 M330' --tab <标签页ID> --pages 2
node scripts/shopping.mjs task-run --task mouse-two-pages
```

先保留第 1 页快照，再预留唯一一次“下一页”点击。点击自身重新校验关键词、地址、分页控件、选中排序及采样商品顺序。确认要求第 2 页地址与分页显示一致、至少出现一个未在第 1 页样本中的商品、两次第 2 页观察的商品 ID 顺序和展示总页数相同。该规则只确认有限页面变化，不核实平台排序算法、总商品量或确定实付；两个样本完全重叠时保守地不确认。

支持当前实际观察到的一或两个可见分页区；必须唯一识别带“上一页／下一页”文字的控件。紧凑分页区只参与核对，两区页码、展示总数和禁用状态须一致；可见 `next-current` 数字标记也须一致。重复完整控件或状态冲突时停止，不随意选第一组。

后续销量实测出现了另一种短分页布局：紧凑区显示 `1/11`，完整区只有连续的 1–11 数字按钮和选中页。此时要求紧凑区提供可见总页数，完整区数字从 1 连续覆盖到该总数（最多 40 页），当前页和禁用状态一致。数字缺失、重复、隐藏或两区冲突均拒绝；不能只用最后一个可见数字推断总页数。

结果 `pages` 含两个 `{search, pagination}`；每页的去重、广告跳过和价格边界与首屏一致。`coverage.page_transition_verified` 仅在上述条件满足时为 true，`sort_verified`、`filters_verified` 和 `total_results_known` 仍为 false。`total_pages_displayed` 只记录 `1/100` 等页面展示，不证明所有页均可取。不同页可能有重复商品，结果按页保留，不虚报跨页唯一商品数。

最多 8 次观察；点击后最多 3 次结果检查，成功观察及动作返回后至少间隔 1.5 秒。超时或进程中断不重发已预留的点击；恢复先观察，继续使用原任务和预算。暂停时 `partial_pages` 保留已确认页面，未确认的第 2 页候选不作为成功结果交付。

地址诊断会返回该任务当前允许的 `allowed_urls`。尚未预留点击时只允许第 1 页；已预留后允许同关键词第 1 或第 2 页，`task-rebind --tab` 使用相同规则。若恢复后仍在第 1 页，也不补发点击。专用连接迁入命令目前仅支持原首屏任务，不支持该模式。

2026-09-22 前两次真实尝试在点击前因结构不匹配停止。用户要求继续后，使用最后一档恢复与 15000 ms 等待保存了真实布局，确认同时存在紧凑和完整两个分页区。修复唯一控件选择并离线测试后，原尝试继续，点击一次“下一页”后遇到验证。用户完成验证后按原任务恢复，两次一致观察确认第 2 页，没有重复点击。原任务 complete：attempts=4、观察=7、点击预留=1、retries=2、等待预留共 20000 ms。两页各扫描 25 张，分别返回 21／13 条记录、跳过 4／12 张不支持卡片；跨页去重 23 件，第 2 页只有 2 件相对首批抽样的新商品。结果逐页保留，不能把 34 条记录称为 34 件不同商品，也不证明全部卡片刷新或全量覆盖。178 项正式测试在 Node.js 22、24 通过；真实证据仅覆盖本次关键词和人工验证后的恢复。

## 有限销量切换（实验性）

`--sort sales` 创建 `search_sort` 任务，只在已有同关键词第 1 或第 2 页、明确选中“综合”时开始。每次观察前 25 张卡片，最多一次“销量”点击；不与 `--pages` 组合，不提交新搜索、不套用筛选、不点击价格箭头或反复切换排序。

```sh
node scripts/shopping.mjs task-start --task mouse-sales --search '罗技 M330' --tab <标签页ID> --sort sales
node scripts/shopping.mjs task-run --task mouse-sales
```

点击自身再次核对原地址、综合选中、唯一且未禁用的销量 tab、分页状态及商品顺序。成功确认要求：同关键词第 1 页、唯一选中“销量”、商品 ID 顺序与点击前不同，且两次连续观察的地址、商品 ID 顺序和分页状态一致。失败或回复丢失后只观察，不重发点击；8 次 DOM 观察、3 次结果检查、1.5 秒间隔及平台暂停规则与两页任务相同。

结果包含 `before`／`after` 两份局部快照，`coverage.sort_ui_verified: true` 仅证明上述界面状态与变化。`sort_verified: false` 继续表示没有验证平台的销量排名算法；卡片“多少人付款”等文案不作为可比较的精确销量。`sort` URL 参数仅保留实际观察到的有限字符值，不推断参数含义，也不构造该地址用于导航。其他筛选参数、重复参数、第三页及其他关键词仍拒绝。开始时已处于销量排序的页面不自动重复点击。

尚未预留动作时，地址只允许无 `sort` 参数的第 1／2 页；有意图后可核对同关键词的排序参数。`task-diagnose` 仍只反映当前窗口的清单，`task-rebind --tab` 按这一意图校验新 ID。销量读取新增原 ID 的地址核对：若原标签页不在当前窗口清单，针对任务明确保存的 ID 只读 `location.href`，确认关键词、页码和允许参数后再执行受保护读取。该步骤不读取 DOM、标题、账号或存储，不输出无关地址，不聚焦／创建窗口，也不发现其他窗口中的新 ID。原 ID 不存在或已变为其他页面时停止；不会退回当前活动标签页。动作和读取仍各自重新校验身份，原计数保留。

结构异常仍停止，不因为切换后可能在加载就自动归类为可重试。暂停时 `partial_search` 保留点击前快照，未确认的候选不作为排序结果；完成的旧快照不补写新证据。

## 展开评价

**最新范围：** 评价只采文字，使用 `--review-categories FILE`，每批一个商品、1–3类、每类前10个主评位置，含最多一次正常面板打开。原鼠标页“全部”“追评”两类各10个主评位置已确认，后者含10条追评文字；保留原格式失败，用户明确授权后两次只读恢复通过，未重复点击。累计11/12读取、恢复2/2，本批完成不填余量。后续既有天猫635398543460自然未展开时自动打开一次，两读确认“全部”8主评及1追评；4/12读取含前置1、零分类动作／重试，页面21条总量与13条折叠提示保留。后续普通淘宝图书也自动打开并两读取得“全部”2主评；图/视频点击选中后文字三次未变，8/12读取、3/3后检查后停止，归属未确认，保留部分成功结果。普通淘宝／天猫各一个自然关闭入口样本通过，不能据此保证全部分类。后续新任务已增加未确认文字交付，保留原观察时间及未确认原因；旧任务不回填，文字重合的归属保护仍在。该新增仅离线验收，376项完整测试双版本通过，无新增平台访问。详见[文字分类采样](review-text-sampling.md)。下方20条和图片字段说明兼容的 --reviews 及历史结果，不能用于新文字范围。

先绑定已打开的公开商品页。输入 1–10 个绑定名：

```sh
node scripts/shopping.mjs task-start --task mouse-reviews --bindings mouse --reviews
node scripts/shopping.mjs task-run --task mouse-reviews
```

程序在已核实商品身份的页面内，寻找评价区域唯一的“查看全部评价”按钮。已存在可识别的评价面板时直接读取；否则最多发出一次展开动作并保留意图，后续检查面板是否出现。完成后保持评价面板打开。

读取及“已展开、不必再点击”的确认都要求实际评价集合容器与视口相交，祖先不能隐藏、透明、inert 或 aria-hidden。只看到 Drawer 外壳或非空布局矩形不够：2026-09-23 实测发现外壳在屏内、内容整体在屏外的情况。此时返回 `REVIEW_DRAWER_NOT_VISIBLE`，停止原任务，保留计数，不自动重试或补点。已在可见滚动面板内加载但位于下方的条目仍可读取，不以逐条视口可见性限制集合。

该保护当时通过331项双版本测试；后续真实可见面板的两类文字读取，以及另一天猫自然未展开页自动打开均已有限验证，见上面的新入口。此前任务 complete、动作预留和 DOM 结果仍不能证明旧面板实际显示，旧数据不回填。详见屏外面板纠错。

每件最多返回 20 条当前已加载的主评正文，保留：

- `total_text`：平台显示的总量文案，可能是“4000+”，不解释为精确总数。
- `loaded_count`／`returned_count`：当前面板加载数／实际输出数，不能替代总量文案。
- `purchase_text`：日期与已购规格原文；仅在匹配已验证格式时拆出 `date_text`、`variant_text`，其他情况保留原文，拆分字段为 null。
- `observation_index`：这次观察内的顺序，不能作为稳定评价 ID。相同正文不合并成一条。

从 v0.4.1 开始，新评价结果的 `schema_version: 2` 增加关联字段：

- `seller_replies`：同一主评区域内的商家回复，最多 2 条；核对“商家回复：”标签后保留原文和正文。
- `followups`：同一主评区域内的追评，最多 2 条；保留原文、“7天后追评：”等已识别的相对时间文案和正文。每条追评也有自己的 `seller_replies`，不会混入主评的回复数组。
- `relation_basis: same_review_dom_container`：关联依据是同一页面评价容器，没有冒充平台评价 ID。不同主评即使正文相同也不合并。
- `fold_notice_text`：已加载区域中的平台折叠提示，例如“已折叠3487条对你帮助不大的评价”；它不是翻页终点证明，也不是被折叠内容的读取结果。

相关原文每条最多 1000 字符，主评最多 2000 字符。所有文本仍可能被页面或上限截断，因此 `text_may_be_truncated: true`。数组为空仅表示本次限定区域未观察到相关内容；不证明该评价从未有追评或回复。不会点击“更多”展开长文，也不会加载隐藏或被平台折叠的评价。

不提取评价者名称、头像、个人主页。新读取的子格式 3 增加所属相册的有限图片位置／缩略图观察，详见下节；评价图片文件导出、分页、排序和款式筛选尚未实现，不将默认展示顺序称为“最新”。空面板只有有限等待，不断言商品没有评价。旧版任务缓存继续按原结果格式返回，不会为过去的观察补造追评、回复或折叠提示。

包含追评和回复的单次评价响应上限为 1 MiB；商品详情读取也使用 1 MiB 上限，其他浏览器命令维持 256 KiB。超过上限会明确失败，不接受任意大小的页面数据。任务检查点仍受整体大小限制。

例如 2026-09-22 的普通淘宝样本显示“用户评价·25”，面板实际加载并返回 5 条；这项操作完成，评价集合仍是局部结果。

同日天猫样本的 20 条主评关联到 19 条商家回复、1 条追评。一轮研究中仅滚动一次到评价列表底部，条数仍为 20，出现平台折叠提示，未识别到可用的下一页入口。因此当前 CLI 不提供追加滚动或自动分页，不能循环滚动来假装取得更多数据。

## 评价子格式 3：关联范围与图片集

新读取输出 `schema_version: 3`，保留子格式 2 的主评、购买信息、追评及回复字段，新增以下内容：

| 字段 | 含义 |
| --- | --- |
| 顶层 `omitted_count` | `loaded_count - returned_count`，仅表示已加载但未返回的条数，不包括未知分页或被平台折叠的评价 |
| 主评 `relation_scope.followups`／`seller_replies` | 每类 `seen`、`returned`、`omitted`；最多各返回 2 条，超出部分不隐藏计数 |
| 追评 `relation_scope.seller_replies` | 该条追评自身的回复范围，与主评的回复分开 |
| 主评或追评 `images` | 所属相册观察、图片位置列表、计数和未验证标记；没有支持相册不等于买家没上传图片 |

字段定位核对所属主评、追评及回复，多个同名候选或嵌套条目停止；主评正文不得借用追评正文，也不把包含另一条目的整段文字拼接进主评。旧无版本格式及子格式 2 原样回读，不补造新字段。

`images` 内部格式 1 包含 `album_observed`、`slots_seen`、`slots_scanned`、`slots_omitted`、`image_links_returned`、`covered_slots` 和 `slots`；每条主评或追评最多扫描 6 个可见相册位置。每个位置保留从 1 起始的 `position`，不按 URL 合并。它只是该次观察中的局部位置，不是平台图片 ID 或评价 ID。

| `slots[].state` | 输出 |
| --- | --- |

## 动作与恢复证据

`action_evidence` 保留动作意图数、页面观察预留数、回复异常错误码。`actions_reserved: 1` 表示动作可能已执行，不保证鼠标点击或跳转一定发生。只有后续页面观察通过才返回结果。

原首屏、旧两页及相应销量／价格观察每个操作最多8次页面观察，间隔至少1.5秒；动作后连续3次未观察到预期页面或已加载面板则停止。网络暂时错误仍按统一预算处理；登录、验证和频控立即交给原暂停机制。旧模式页面返回已知“未派发”错误时才释放该次动作意图；新多页模式已预留的意图不退款，预算见独立指引。明确恢复、重启或更换连接都不清零计数。

这些上限只是本地控制参数，没有证据表明它们能保证平台不触发风控。完整任务与数据覆盖率分别解释，不把 `complete` 当作全平台能力已验收。

## 可见控件与价格入口检查（实验性）

以下两种模式使用同一关键词已打开的第 1／2 页，互斥且不与 pages、sort 或商品模式组合：

```sh
node scripts/shopping.mjs task-start --task mouse-controls --search '罗技 M330' --tab <标签页ID> --inspect-controls --state-dir <原状态目录>
node scripts/shopping.mjs task-run --task mouse-controls --state-dir <原状态目录>
```

`--inspect-controls` 创建 `search_controls`，只读前 25 张卡片、分页与可见排序控件。至多 8 个 tab，子节点至多两层且每层 12 个；元数据包括可见文字、class、选中／禁用及有限 ARIA 字段。只读一次成功观察即完成，失败观察仍预留，累计最多 8 次。不会点击、导航、滚动或悬停；结构信息不能证明控件行为。

需要验证一次价格入口交互时，用独立的 `--inspect-price` 替代 `--inspect-controls`，创建 `search_price_entry`。它先保存 `before`，再次核对地址、分页、商品顺序和排序栏文字，再向唯一未选中、未禁用的“价格”tab 派发一次 DOM click；至少等待 1.5 秒后保存 `after`。只有在前一任务完成且确实需要这一独立动作范围时创建，不能借此绕过停止或刷新预算。不得将它称为价格排序命令。

价格入口结果在 `before/after.inspection` 中保存同样的卡片及控件，`before/after.entry` 保存至多 600 字符的排序栏文字，以及至多 6 个含价格方向文字的可见 role=menu/listbox 候选（每个最多 600 字符）。候选不宣称属于该价格入口；缺失不证明没有其他结构的菜单。`price_direction` 固定 null，`control_behavior_verified`、`menu_relation_verified`、`sort_verified`、`filters_verified` 均为 false。没有可见变化也可以完成描述性检查，不能自动重发 click 或选择方向。

累计最多 8 次 DOM 观察、一次点击意图。暂停时报告 `partial_inspection`；恢复保留动作及失败预算，点击回包不明后只读。验证码自动重试为零。两种模式均允许原关键词实际观察到的有限 sort 参数，且支持原保存 ID 的固定地址核对；不从参数推断方向、不构造 URL 导航。新 ID 重绑仍需当前窗口元信息匹配。

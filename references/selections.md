# 指定规格组合与价格观察

当用户需要查询明确规格的商品时，先读取商品快照中的规格维度和选项，再创建组合计划。计划会改变商品页的规格选中状态，结束后停留在最后处理的组合。

当前最多 20 个组合，每个组合 1–8 个规格维度。不穷举所有组合；每项必须覆盖商品快照中的全部维度，包括已经默认选中的单选维度。标签用原文，不按名称猜测型号。

普通商品读取已经包含每个支持维度的已加载选项，输出清单时不需要逐项点击。需要某几个组合的展示价时才使用本模式；没有观察过的组合不复制当前价格、不从选项相乘生成 SKU 表。新快照的 `specification_scope` 说明可见选项是否被读取上限截断；若有组或选项被省略，点击与组合确认均以 `SELECTION_AMBIGUOUS` 停止，预算保留。

## 输入与命令

将以下 JSON 保存为 `selection-plan.json`，使用已经存在的绑定名称和实际页面选项：

```json
{
  "schema_version": 1,
  "items": [
    {
      "binding": "mouse",
      "selection": [
        { "group": "颜色分类", "option": "M330-黑色*" }
      ]
    },
    {
      "binding": "mouse",
      "selection": [
        { "group": "颜色分类", "option": "M330-黑色+短款鼠标垫*" }
      ]
    }
  ]
}
```

```sh
node scripts/shopping.mjs task-start --task mouse-combinations --plan selection-plan.json
node scripts/shopping.mjs task-run --task mouse-combinations
node scripts/shopping.mjs task-status --task mouse-combinations
```

`--plan` 与 `--bindings` 二选一。计划路径相对当前工作目录解析，计划内容会复制进检查点；后续修改计划文件不会改变既有任务。相同商品与相同组合去重，调整维度排列顺序不会获得新额度；同一商品的不同组合会分别记录。

## 执行与恢复

1. 检查连接、商品身份及验证／频控信号，读取当前规格。组合缺维度、标签不唯一或选项禁用时不点击。同一规格组出现多个选中标记时返回 `SELECTION_STATE_CONFLICT`，停止当前平台任务，不自动重试或继续其他组合。
2. 跳过已经选中且未观察到禁用标记的选项。在发出其他选项点击前，先将该次意图写入检查点，并再次拒绝多选中冲突；只通过已支持的规格区域定位，不接受任意选择器或脚本。`aria-disabled`、`data-disabled` 和已支持的禁用 class 均参与判断。
3. 点击后至少间隔 1.5 秒再观察。工具报错也先核对页面；同一个可能已经发出的点击不会自动重发。最多检查 3 次仍未观察到该选中状态时，返回 `SELECTION_OUTCOME_UNKNOWN`，停止本轮。
4. 所有维度匹配后观察价格，通常间隔至少 1 秒；连续 3 次价格读数相同且跨越至少 2 秒，记录稳定信号。进入该阶段后的后续读取最多 8 次，每组合全部 DOM 读取最多 40 次，这些预算也跨进程保存。

平台任务的临时故障重试和恢复上限继续适用，见 [任务说明](tasks.md)。DOM 观察次数单独列出，不能把一次组合操作内部的有限检查误当作无限自动重试。每个维度最多保留一次可能发出的点击；若程序在点击之前已明确返回验证或连接错误，则可在问题解除后首次发出该点击。

日常扩展只列当前窗口。若清单缺少任务保存的商品 ID，普通快照、详情及规格点击会先在该精确标签页核对公开商品地址；同商品才继续固定读取／点击，页面内仍会再次校验身份和验证信号。不会聚焦窗口、遍历其他窗口或改用活动页。地址不符、登录跳转或地址核对失败时停止，点击前失败标记为未派发；点击回包不明仍保留原意图，不补发。此路径仅适用于扩展清单缺失，不适用于已列出的错误目标或专用浏览器。

进程被终止后，恢复同一任务会先检查持久化的点击意图和页面状态。价格检查中断也不清零读取预算。已经确认的选项后来被页面或用户改变时停止，避免覆盖无法解释的状态变化。重新接回同一商品的新标签页时，所有未完成组合的定位一并更新；未知点击结果仍需观察确认，不能自动重做。

## 返回结果

结果保留普通商品快照字段，另附 `selection_evidence`：

| 字段／值 | 含义 |
| --- | --- |
| `status: confirmed` | 观察时，计划内每个维度仅有一个选中项，且为指定选项，没有看到其禁用标记 |
| `changed_and_stable` | 与首次规格操作前相比，展示价格或其标签发生了变化，随后取得稳定读数 |
| `unchanged_after_selection` | 组合已选中，但价格读数与操作前相同；不能判断这是同价还是更新尚未完成 |
| `existing_selection_stable` | 原本就选中了所需组合，无需点击，取得稳定的展示价格 |
| `range_or_unparsed` | 稳定读数仍是起价、范围或未能解析的价格 |
| `unstable`／`not_observed` | 在观察预算内没有取得稳定价格／没有读到价格区域 |
| `action_count`／`observation_count` | 为该组合保留的选项操作和 DOM 读取次数；中断可能导致计数已保留而操作未真正发出 |

`changed_and_stable` 不证明价格变化一定由规格引起，也不能排除更晚的异步更新。当前没有取得能直接将平台 SKU ID 与该价格绑定的证据，因此 `sku_price_binding_verified` 仍为 `false`，`sku_id` 仍为 `null`，优惠资格同样未确认。向用户表述为“指定组合选中后观察到的页面展示价”，不表述为确定实付或完整 SKU 数据。

新观察另有 `sku_evidence`，记录同次读取的地址栏 `skuId` 候选。只解析已经验证目标身份的当前 URL，不打开带候选 ID 的新链接；数据含义见 [商品字段](products.md)。价格稳定计数仍只针对价格，不表示 URL 候选稳定或候选已认证。选项选中、价格稳定、URL 候选存在三件事都成立，也不会自动设为已验证 SKU 价格。

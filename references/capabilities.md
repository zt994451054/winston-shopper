# 能力清单（2.0.6）

本 Skill 只读，三个平台共用同一套命令和规则。下面列出每个平台**能读什么、读到什么程度、明确不做什么**。“实页通过”指在真实页面上验收过，并在两轮完整复测里再跑过；它只代表验收过的样本，不保证所有商品和布局。

每项的命令写法见 [SKILL.md](../SKILL.md)，参数全集见[命令接口](commands.md)。

## 公共能力（三个平台都有）

| 能力 | 说明 |
| --- | --- |
| 环境检查与准备 | `setup` 依次检查依赖、扩展和令牌并给出下一步，`setup --install` 按锁安装依赖，`setup --open-store [--new-profile]` 打开扩展商店页（可新建专用资料）；用户在扩展里点“复制”后 `token-save` 从剪贴板保存令牌（`--dialog` 弹框备用）；`bridge-start` 在只有一个资料装了扩展时自动选用，多个资料连接失败时提示每个资料令牌不同，以后复用常驻服务；`doctor` 只检查、不启动或重连，零页面也就绪；`bridge-stop` 明确停止 |
| 打开、列出、关闭页面 | `page-open` 打开搜索页、商品页（淘宝、京东）、订单列表、购物车（淘宝、京东）；`tabs` 只列本次 Playwright 连接能看到的页面，看不到用户自己打开的页面；`page-close` 只关本程序打开的页面 |
| 任务 | `task-start` 只保存计划，`task-run` 执行；结果、观察时间、覆盖范围和缺项都保存在本地状态目录 |
| 操作节奏 | 每次页面操作之间随机间隔；搜索类、页面类加载按平台各有次数上限（拼多多更低），用完就暂停到允许的时间 |
| 遇到拦截就停 | 登录页、验证码、限流页出现时先保存暂停状态，再显示对应页面一次；显示失败保留原错误。等用户处理后用 `task-resume` 继续，期间服务保持运行 |
| 中断恢复 | 页面被关、窗口切换、连接断开时可诊断（`task-diagnose`）、重新绑定（`task-rebind`）后在原任务上继续，不重置额度 |
| 断网回读 | `task-status` 只读本地保存的结果，不访问浏览器 |
| 报告导出 | `report-export` 把任意一个任务的结果导出成 Markdown 或 CSV；不含收货人、地址、电话、支付和物流单号 |

## 淘宝／天猫

| 板块 | 能读什么 | 范围与限制 |
| --- | --- | --- |
| 搜索 | 标题、链接、显示价、店铺、销量文字；跳过广告卡片 | 1～5 页，每页最多看 50 张卡片 |
| 搜索排序与筛选 | 销量排序；价格升序、降序；价格区间；只看天猫；包邮。价格类可组合并翻 2～5 页 | 销量排序只读第 1 页；包邮以外的筛选不做 |
| 商品详情 | 标题、店铺、参数、运费和发货、服务标签；规格名称及选中、不可选标记；展示价；详情长图链接；正文文字 | 一次最多 10 件 |
| 规格 | 全部规格及对应图片；指定规格组合选中后的展示价（最多 20 个组合） | 展示价不是实付价；平台 SKU 编号和价格的确切对应没有直接来源 |
| 图片 | 顶部图集；指定缩略图对应的主图（最多 3 张） | 只给图片链接，不下载文件，不做内容解读 |
| 服务说明 | 打开服务浮层读一级说明 | 二级完整规则不读 |
| 评价 | 按分类读文字，最多 3 类，每类前 10 条，含追评和商家回复 | 不翻页，不读评价图片和视频 |
| 购物车 | 已加载的行（1～50 行，每批 5 行）；每行判为不能购买（附原因原文）、所选款式缺货、未见失效标记或无法归类 | “未见失效标记”不等于一定能买；全车总数页面不显示 |
| 订单列表 | 已加载的订单；或从第 1 页起读 1～10 页，到最后一页自动停 | 回收站、按状态或搜索筛选不做 |
| 单个订单 | 从列表第 1～5 单进入，读详情正文：状态、前 10 件商品、金额原文 | 金额是页面原文，不是结算证明 |

## 京东（`--platform jd`）

| 板块 | 能读什么 | 范围与限制 |
| --- | --- | --- |
| 搜索 | 卡片的商品编号、标题、店铺、销量区原文（可能含好评率）、显示价及旁边的灰色金额、自营和广告标记 | 只读每页首屏（一般 30 张，最多 60 张）；1～5 页，每页点一次“下一页” |
| 搜索排序与筛选 | 销量、价格降序、价格升序；价格区间（整数元）；可再翻页 | 其他筛选不做 |
| 商品详情 | 标题、价格、店铺、自营标记、亮点参数、服务标签和说明、同组规格、“商品详情”区、默认评价区 | 最多滚动一次到“商品详情”区；同组规格只列名称，不套用当前价格（每个规格是独立商品） |
| 分类评价 | 打开“全部评价”，读 1～3 个分类已画出的 3～4 张卡片 | 不滚动；后台页面由程序先显示，仍不可见时才请用户处理 |
| 购物车 | 已加载的行；每行判为不能购买、未见失效标记或无法归类 | 不滚动，所以只有页面一开始画出的那部分（实测约 10 行） |
| 订单列表 | 已加载的订单卡片，包括拆单的子订单；时间范围原样记下 | 不滚动、不翻页 |
| 单个订单 | 点一次“订单详情”读新开的详情页后关闭；支持两种版式 | 用户要先允许 order.jd.com 弹出窗口；旧版式页面上的订单号认不出（记为空）；拆单子订单的详情页没验收过 |

## 拼多多（`--platform pdd`，手机网页版）

| 板块 | 能读什么 | 范围与限制 |
| --- | --- | --- |
| 搜索 | 卡片的标题、价格、销量文字、标签、主图地址 | 只读已画出的卡片（一般约 20 张，最多 40 张），其余只计数；卡片没有商品编号，标题是截短的；不往下加载 |
| 搜索排序与筛选 | 销量、价格升序、价格降序；价格区间（在“筛选”里设） | 其他筛选不做 |
| 商品详情 | 点搜索结果第 N 张进入，读编号、完整标题、价格及优惠说明、主图、发货和服务文字、规格名称和“已选”、店铺、评价总数和 2～3 条预览、参数、详情图地址 | 只从搜索卡片进入，不直接打开商品链接；价格被页面隐藏的商品跳过 |
| 各规格价格 | 打开底部每个购买按钮的规格抽屉，逐个点没选中的选项，读每次点击后的价格和“已选” | 每个抽屉最多点 12 次，没点到的写进缺项；灰掉的缺货选项不点；不点“确定”，不改数量，不进订单页 |
| 评价 | 点一次“查看全部”，读“全部”里已加载的评价：规格、正文、日期、追评、商家回复，评价图只记张数 | 最多 20 条，不滚动，不读评价人名称 |
| 订单列表 | 已加载的订单卡片：商品、规格、数量、金额、状态 | 不滚动；列表上没有订单号 |
| 单个订单 | 点一次商品名称进入，展开一次“查看更多订单和优惠信息”（没有优惠的订单写作“查看更多订单信息”），读状态、商品、金额和时间 | 不读收货人、支付和物流 |
| 购物车 | — | 拼多多没有购物车 |

## 明确不做的事

- 加购、下单、付款、拼单，修改购物车、订单、地址或账户设置，提交评价或售后。
- 读取 cookies、浏览器存储、联系人、收货信息、支付方式或物流单号。
- 自动登录、自动过验证码、伪造鼠标轨迹、隐藏自动化痕迹、修改浏览器指纹。
- 下载图片和视频文件（只给链接，调用方需要时自己取得）；视频播放和转写；图片内容的解读（交给调用方的 AI）。
- 比较、推荐和摘要：Skill 只交付带来源的原始观察，由调用方判断。

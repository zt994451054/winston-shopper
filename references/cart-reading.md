## 能否购买（2026-10-13）

2026-10-13 起，新建的购物车任务（`--cart` 和 `--cart --cart-rows N`）在每一行加上 `availability`，只按页面上明确的文字和控件信号判断。判断依据来自实页调查，实页验收见记录。2026-10-14 起按规则 2 判断，允许商品图上出现促销字样，见记录。

| `status` | 页面信号（必须全部满足） | 含义 |
| --- | --- | --- |
| `cannot_buy` | 商品图上恰好一条文字“商品下架”或“不可购买”；详情区恰好一条提示；勾选框灰；规格、价格、数量三处都带失效样式 | 不能购买。`reason` 是详情区提示原文，例如“宝贝已不能购买”“商品库存不足”“店铺已关闭，宝贝不能购买，请谅解” |
| `variant_out_of_stock` | 商品图上恰好一条“款式缺货”；没有详情提示；勾选框灰；只有价格带失效样式 | 所选款式缺货。换别的款式是否能买，没有核实 |
| `no_marker_seen` | 详情区没有提示；勾选框可勾；三处都没有失效样式；四个区域都找到。图上可以有促销字样（如“全网低价”），但不能是“商品下架”“不可购买”“款式缺货”，也不能被截断 | 只表示没看到失效标记，不等于能买；价格和库存都没有验证。图上的字样保留在 `signals` |
| `unrecognized` | 其他任何组合，包括区域缺失、勾选框不是恰好一个、文字被截断、图上有失效字样而勾选框可勾 | 不猜，原样交付 `signals` |

- `signals` 保存原始信号：图上文字（`image_texts`）、详情提示（`messages`）、各勾选框是否禁用（`checkboxes`），以及 `specification_invalid`、`price_invalid`、`quantity_disabled`。区域没找到时对应值为 `null`。勾选框只读是否禁用，不读它的值（可能含购物车内部编号）。
- `purchase_verified` 始终为 `false`。
- 每个快照和分批任务的结果都有 `availability_summary`，统计四种状态的行数。
- 格式：单次快照为格式 4，分批快照为格式 5，新分批任务为 `cart_collection` 格式 3，结果为格式 2。以前保存的格式 1～3 快照和格式 1 分批任务原样可读、可导出；格式 1 分批任务续批时仍按旧格式读取，不混入新格式。
- 规则版本：规则 2 的结果每行带 `classification_version: 2`。2026-10-13 的规则 1 要求图上没有任何文字，它的结果没有这个字段，复核时仍按规则 1 重算，内容不变。`cart_collection` 格式 2 是规则 1 时期开始的分批任务，续批仍用规则 1；格式 3 用规则 2。同一结果不混用两种规则。

## 分批读取：新任务

新入口 `--cart --cart-rows N` 先保存本次前N个已加载行的范围（N为1–50），创建独立 `cart_collection`；每次最多读5个新位置。50是此阶段的有限保护，不是平台上限，也不表示全车采集。已有完成的 `cart_snapshot` 仍只回原前5行缓存，不升级或追加；不得为了填旧任务剩余额度、绕过停止任务或扩大原请求范围而换任务。

```sh
node scripts/shopping.mjs task-start --task <本次新请求名称> --cart --cart-rows 10 --tab <当前购物车标签ID> --state-dir .runtime/verification-bindings
node scripts/shopping.mjs task-run --task <同一任务名> --state-dir .runtime/verification-bindings
node scripts/shopping.mjs task-status --task <同一任务名> --state-dir .runtime/verification-bindings
node scripts/shopping.mjs task-next-batch --task <同一任务名> --state-dir .runtime/verification-bindings
```

首批成功后若还有范围，状态为 `awaiting_batch`，普通 `task-run`／`task-status`只回缓存；明确续批才执行 `task-next-batch`。每批先保存累计读取次数，再刷新原连接与tabs，正常批次间隔1500ms；最后一批可以少于5行。初次已加载行少于N时，只读该已加载范围，保留 `requested_limit_reached:false`，不滚动补行。`complete`只表示本次已加载范围完成，页面总量及full_cart仍未知／false。

整个任务最多 `ceil(N/5)+2` 次读取（最高12），包含失败、中断及目标预检；自动重试共2次，显式恢复共2次，每次5秒，沿用原共享平台重试／等待预算。续批不重置这些计数。更早达到其他限制也会结束，保留已有批次，不凑满读取上限。预算不足以同时用尽每一种恢复额度。

续批表达式先核对当前已加载行数，再逐一比对所有已读位置的规范商品链接、完整标题、店铺区域、规格区域及数量；此前行只重读这些保护字段，不重新采价格／状态区域。已读行数或这些值变化时报 `CART_ROWS_CHANGED`，停止采集新位置。首批字段不足以生成保护时报 `CART_CONTINUITY_UNVERIFIED`，仍交付已读数据。旧价格保持原时间，价格单独变化不作为行身份变化。值相同不证明物理行或账户连续性；完全相同的重复行互换不能凭此识别，不按商品ID去重。

数据始终在 `operations[0].cart_collection`：包含 `batches[{attempt,snapshot}]` 与按原位置展开的 `rows`，每行保留所属批次的 `observed_at`。完成后同样放进 `result`。每批快照格式2包含 `range`、`prefix_guard.positions_checked`、观察时间及原同行字段；格式1快照保持不变。停止、结束、等待用户或连接时，先前批次仍可离线交付。实际值只留私有状态，公开测试使用合成数据。

分批链已有一例真实购物车正例：新正常前10行任务分两批各5，第二批先核对此前5位置；读取2/4、恢复／重试0，取得10组标题链接／规格／店铺区域、10数量及16价格组件，DOM30／返回10／省略20。创建→首批→同任务续批→完成→禁用HTTP的CLI缓存回读通过。两批观察时间分别保留，未新开页、滚动或改购物车；故障恢复、变化保护及最多50行仍仅离线覆盖。旧1325状态全不变，仅新增任务／收据2份共1327；本批complete，只回缓存，不填余下2次。见本轮实现与保全。下方前5行报告保留原时点。

## 正式命令与预算

以下无 `--cart-rows` 的入口仍是前5行单批任务；恢复规则也适用于上方的新分批任务。运行前确认Node.js 22+，先doctor／tabs，从当前窗口选择明确的购物车标签。购物车无需商品绑定，只接受已观察的 `https://cart.taobao.com/cart.htm`；查询／片段不保存。新正常请求可调用：

```sh
node scripts/shopping.mjs task-start --task <本次新请求名称> --cart --tab <当前购物车标签ID> --state-dir .runtime/verification-bindings
node scripts/shopping.mjs task-run --task <同一任务名> --state-dir .runtime/verification-bindings
node scripts/shopping.mjs task-status --task <同一任务名> --state-dir .runtime/verification-bindings
```

`task-start`只在本地创建一个 `cart_snapshot` 操作，不读取页面。`task-run`先落盘预留一次，再刷新连接／tabs核对保存的标签；地址变化或缺失就暂停，不借用另一个同地址标签。通过后执行一次同时保护地址和读取行的固定表达式，避免单独地址DOM读取扩大预算。最多返回前5个已加载行，不翻页／滚动，不勾选、修改数量、删除、领券或结算。

| 保护 | 固定上限和含义 |
| --- | --- |
| 行范围 | 前5个已加载DOM位置；同商品不同位置分别保留，名称或商品ID不用于合并 |
| 读取预留 | 最多6次，失败、执行中断和目标预检失败都保留；其他限制可能更早结束 |
| 自动故障重试 | 延续共享策略：本操作最多2次，等待5秒／15秒，平台累计最多5次 |
| 显式恢复 | 用户／连接／冷却恢复合计最多2次；每次先保存预留并等待5秒，占原120秒等待预算 |
| 频控 | 继续暂停，只有明确请求才做一次冷却探测；失败不自动重复 |

`operations[0].cart_budget`返回固定范围、读取／恢复预留及最多6项安全错误历史。历史只包含attempt、code、category；不保存外部错误原文。恢复中的用户／连接检查遇到暂时故障仍暂停，不自动连读。冷却探测遇到新的登录／验证提示仍暂停，共用原恢复上限；其他故障停止。等待阶段中断后，原等待和恢复预留保持，不再次占用额度；读数已预留却没有结果时按 `READ_INTERRUPTED` 处理，不退款或重置。

遇到登录／验证：用户完成该标签上的步骤后，用同任务 `task-resume --after-user`。连接恢复用 `task-resume --after-connection`；标签ID变化时先 `tabs`，再 `task-rebind --task <同一任务名> --tab <新ID> --state-dir .runtime/verification-bindings`，随后恢复。重绑必须匹配原端点及购物车路径，只检查地址清单，预算与失败历史不变，不证明账号连续性。冷却需要明确请求，使用 `task-resume --after-cooldown`。上述恢复命令均带同一 `--task` 和 `--state-dir`。

成功数据在 `operations[0].result`，`complete`只表示此次前5行范围取得，`coverage.status`仍为partial。重复task-run／task-status重新校验缓存并离线返回原时间的结果，不刷新页面；保存结构或派生数量被篡改时，先以 `INVALID_CHECKPOINT` 停止。范围／字段不支持或额度耗尽就结束本轮，不换任务／状态目录继续。显式task-end仅记录结束，保留所有原结果和次数。

空车、全车总量和其他布局仍待证据（失效判断见本页开头）；空白或不支持结构不当作空车。实际购物车值只留本地，新任务文件0600、创建的任务目录0700；公开示例与测试只有合成值。正式正常创建／单读／保存／缓存已实页通过，故障恢复仍离线验收，不把此前研究快照迁成正式任务。原 `cart-reading-20261003` 已结束于5/6，不使用本入口填余下1次；新cart-snapshot任务也已完成，仅回缓存。

## 地址保护接口

[cart-target.mjs](../lib/cart-target.mjs) 的 `parseCartUrl(value)` 仅接受已观察的HTTPS域名与 `/cart.htm` 路径，移除查询和片段；拒绝凭证、其他端口、域名或路径。不借用商品绑定，不产生商品ID或SKU ID。

[BrowserBridge.readCartTarget(tabId, target)](../lib/bridge.mjs) 在指定标签执行一次固定地址表达式，返回 `{url, page_state: 'not_assessed'}`。目标错误、已知登录域、连接或回包错误即停止；不自动重试或更换标签。调用方必须先刷新tabs，并在原预算落盘预留。地址通过只确认来源，不能确认登录成功、页面已就绪、商品行存在或购物车为空。

独立地址保护不读取DOM、账户、cookie、storage或网络响应。原14项回归及双Node各687完整测试为前轮基线；独立 `readCartTarget` 方法仍仅模拟验收，固定地址表达式／验证器已有前轮组合观察、行读取及本次正式流程实证，行读取器见上方验收。

## 首批范围

评价本轮结束且目标购物车页明确后，复用原日常Chrome与`.runtime/verification-bindings`，先查tabs并核对页面地址。只检查当前已经加载的前5个购物车商品行，不滚动加载更多，不操作勾选、数量、删除、领券、结算或购买控件。需要登录／验证码时暂停。

先区分真正购物车行与推荐商品、店铺汇总和结算汇总。逐行读取标题、规范商品链接、店铺、规格原文、数量控件当前值、展示价格原文与标签、明确失效提示。未取得的字段保留null及原因，不根据邻行补值。

- 商品ID、规格属性值和本地行序号都不能冒充平台SKU ID。没有直接证据时，SKU ID仍为null。
- 数量与价格归属必须来自同一商品行；行单价、行金额、选中合计、全车总量分别保留，不互相代替。
- 保留条件价格及观察时间，不把优惠价或数量乘单价写成确定实付。
- 同商品不同规格分别保留；没有稳定行ID时不凭标题或商品ID静默去重。
- 未读取的行数和页面显示总量分开。页面空白、未加载、登录或结构不支持都不等于空车；只有明确空车提示和正常页面证据才返回空车。
- 不读取账户昵称、地址、手机号、付款资料或订单信息；实际购物车结果保留本地，公开测试使用合成数据。

首批已有真实结构及读取器证据，仅支持上述限定关系，不猜其他布局。正式命令／保存／有限恢复现已离线接通；全车读取未实现，不能用新任务绕过未结束的停止或重放本次已完成范围。
